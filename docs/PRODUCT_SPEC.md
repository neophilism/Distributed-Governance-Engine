# Distributed-Governance-Engine product requirements

The complete cross-product requirements, feature list, differences, governance rules, private/public boundaries, walkthrough and monetization are in docs/ARCHITECTURE.md. This copy is kept in every repository so implementation does not depend on chat memory. The owning repo's canonical work units are registry/prs.json and detailed docs/prs/ files; update specifications and plan together.

Source request: owner, October 16, 2026. Required modes: collaboration can adopt exact voted text through frozen governance; public-input preserves the original document while collecting proposals, structured ranked arguments and advisory votes. Public documents require periodic/final blockchain commitments; private organizations may opt in and default off. Legislation votes default equal; corporate shareholder votes default to exact record-date voting units, with class/proxy/capacity rules. Neither community adoption nor a share purchase creates legal authority by itself.

Acceptance is a deployed, tested real multiuser application with the planned legal editor, proposal/discussion/vote, signatures, verification and scoped admin flows. Foundation acceptance does not substitute for product acceptance. The owner's human review is deferred until completed deployment; no preliminary audit approval is requested.
